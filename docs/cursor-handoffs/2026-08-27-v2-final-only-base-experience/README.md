# Try Me Now V2 final-only base experience

This package is the execution contract for the next Try Me Now V2 increment. It blends the accepted messaging-compiler architecture with the compatible visual patterns from the Try Folloze storyboard.

The product promise is direct:

> Give Folloze a company, an offer, an audience, and an outcome. Within 60 seconds, receive one finished, source-grounded, on-brand buyer experience.

The visitor does not see a provisional page. They see a calm, credible build state followed by the finished HTML experience.

## What changes

1. The research plan becomes an executed, typed Evidence Graph.
2. The Evidence Graph compiles into one evidence-bound Campaign Thesis.
3. Three materially different strategy candidates compete before any section copy is written.
4. A page recipe determines the semantic buyer journey.
5. A composition family determines the visual arrangement without changing the argument.
6. Section briefs give each writer one job, one buyer movement, evidence, constraints, and continuity.
7. Production model writers become authoritative when they pass the quality gates.
8. A persuasion review ranks valid candidates after factuality and schema gates pass.
9. Every section records whether it came from the model, a repair, or deterministic fallback.
10. The UI shows only intake, honest build progress, recoverable failure, and the final reveal.

## What remains

- Existing canonical `ExperienceSpecV2` and deterministic renderers.
- Existing Launch, Guide, and Align strategic and composition metadata.
- Existing brand authority, safe-fetch, stale-revision, privacy, and trace boundaries.
- Existing app-hosted HTML lifecycle. No Folloze publication.
- Existing 60-second customer-facing deadline.

## What is deliberately deferred

- personalized account and persona variants;
- customer-facing analytics demonstrations;
- save, publish, vanity routing, and email delivery;
- Content Magic expansion;
- a visitor-facing template or strategy picker;
- a broad rewrite of all recipes before one recipe is proven;
- new research providers or credentials.

## Delivery model

Cursor implements the bounded work orders in this package. Codex owns architecture, integration review, benchmark scoring, browser QA, and the keep-or-correct decision. Cursor must not commit, push, deploy, read secrets, or touch unrelated user-owned evidence files.

The previous package at `docs/cursor-handoffs/2026-08-27-messaging-compiler-autoresearch/` remains historical evidence for the first compiler slice. This package supersedes its provisional-preview assumption and extends the compiler rather than replacing it.

## Files in this package

- `architecture.md`: canonical runtime and artifact model.
- `work-orders.md`: bounded implementation sequence.
- `acceptance.md`: release gates and autoresearch rubric.
- `cursor-prompt.md`: coordinator prompt for Cursor.
- `autoresearch/autoresearch.md`: custom experiment loop for this release.

## Completion signal

The work is complete only when:

1. product or solution fixtures render one final artifact with no public provisional HTML;
2. research evidence materially changes the Campaign Thesis and rendered copy;
3. the selected recipe, strategy, section jobs, writer sources, and evidence references are visible in private diagnostics;
4. a deliberately generic or unsupported candidate loses or is rejected;
5. final readiness is persisted and read back within 60 seconds;
6. automated, visual, privacy, and secret gates pass;
7. Codex independently scores two consecutive runs at 90 or higher with no blocker.
